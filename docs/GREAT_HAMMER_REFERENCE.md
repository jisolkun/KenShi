# 大锤：附件源码参考与原创动作边界

本次参考对象是用户上传的 `src.zip`，核验时解压目录为 `/tmp/kenshi-hammer-reference/src`。研究只读取源码和数据，用独立的数据解析器检查 JSON 元数据、Base64 姿势表及曲线结构；没有运行附件脚本，也没有将附件文档中的指令视为项目要求。以下文件定位均指**附件的 `src/`**，不是当前项目同名文件。

## 实际找到的参考

附件的武器目录包含长剑、白牙矛、双刀及武将使用的弓、魔法球、棍，没有独立的大锤武器族：`profile.js:15–25`、`reference-motion-data.js:546–553`、`reference-attack-rules.js:7`。连续曲线目录中也没有名称含 `hammer` 的动作。`reference-combat-audio.js:8` 的 `reference-hammer.mp3` 被绑定到 `executionKick`，不能据此声称已经找到原版大锤动作或大锤音效。

因此，新大锤参考的是附件中的**枪戟五段攻击、共享蓄力重击以及它们的身体与反馈组织方式**。这些文件记录了附件作者对 Android 2.0.0 数据的对应关系；本次核验能确认附件如何实现这些关系，没有独立审计原游戏二进制，也不将其注释自动等同于官方原算法。

## 源码里的实际节奏

枪戟数据表中的 `attackSeconds` / `duration` 使用 `atkspd=0` 的基准值。当前附件默认主角枪戟使用 `.02`，必须通过 `referenceAttackDuration()` 重新换算。不能把元数据的基准总长称为默认游戏总长。

| 源攻击 | 基准攻击段（秒） | 恢复段（秒） | 基准总长（秒） | 默认枪戟总长（秒） | 默认挥击特效延迟（秒） |
| --- | ---: | ---: | ---: | ---: | ---: |
| `attack1_halberd` / 630 | .556 | .417 | .972 | .929 | .130 |
| `attack2_halberd` / 631 | .833 | .278 | 1.111 | 1.047 | .400 |
| `attack3_halberd` / 632 | .833 | .556 | 1.389 | 1.325 | .480 |
| `attack4_halberd` / 633 | .556 | .556 | 1.111 | 1.068 | .340 |
| `attack5_halberd` / 634 | 1.250 | 无独立恢复段 | 1.250 | 1.154 | .380 |

计算式为 `attackRaw / (.24 + atkspd) + recoveryRaw / recoverySpeed`，见 `reference-player-stats.js:37–38`。普通攻击特效的延迟也减去 `atkspd`，见 `combat.js:365–366`。延迟是特效启动时刻，**不是整段伤害持续时间，也不是锤头接触的通用相位**。挥击规则使用 20 fps、4 帧显示、约 .10 秒碰撞有效窗口；`splash` 显示 1.5 秒但碰撞仅 .20 秒。

前四式的恢复段约占基准总长的 43%、25%、40%、50%。第五式虽然没有单独的恢复片段，动作本身仍有长收势；不能把 `recoveryRaw=0` 理解为命中后立刻回到待机。连击控制也没有给每个恢复段重新添加完整宽限时间，见 `reference-control.js:112–123`。

共享蓄力重击应分两段理解，见 `reference-motion-data.js:558` 的 `hero.halberd.charge/heavy`：

- `attackex2`，`sharedassets2.assets / pathId 240`：原始长 `.200000763`，速度 `.24`，播放约 `.833337` 秒。
- `attackex2_impact`，`pathId 241`：原始长 `.233333588`，速度 `.25`，播放约 `.933334` 秒。

前段另由蓄力状态驱动：`reference-power-charge.js:7–10` 以 `.6/s` 累积至 `.5` 后，在后续显示更新中启动重击；`combat.js:573–581, 1840–1856` 完成状态切换。因此 `.933` 秒只是重击释放与恢复段，不含前面的蓄势。约 1.77 秒可以表达这两段的量级，不能作为不受显示帧和控制状态影响的精确实机帧数。

## 解码姿势后能确认的身体特征

独立按 `reference-motion-table-codec.js:3–61` 的格式解码了枪戟五式及共享重击的 `61×88` 姿势表。每一行是导出的低模映射姿势，包含髋位移、各骨骼四元数、武器端点和握点；它不是敌人伤害日志或主角世界根坐标。以下时间用表中的 `atkspd=0` 基准时长换算，采样间隔约 16–23 毫秒，只用于描述动作组织：

- 第二式的武器先从身后向高处带起，再绕身体甩向前方近地位置；约 `.44–.56` 秒，武器由后侧高位转到前方低位，同时髋明显下压。手臂运动伴随髋与胸躯转向。
- 第三式起于前方低位，先提起武器，再转腰带出绕身轨迹；后半程仍继续转身和回收。不能单凭 `rising` 布尔值把整式命名为纯上挑。
- 第四式包含明显侧向绕身、胸躯与髋转动以及髋向前的局部位移。局部髋移动不能替代 `combat.move()` 的实际根推进。
- 第五式的高速度变化集中在约 `.46–.54` 秒，之后还有约 `.7` 秒的绕身与回收。这个短释放、长持续收势的差异适合表现重武器惯性。
- `attackex2_impact` 在释放段前约 `.05–.12` 秒出现集中高速运动，随后髋压低、武器留在前方低位并逐渐收回；蓄势主要来自前一段 `attackex2`，不能把这段快速开头误写成没有蓄势的完整重击。

这些观察支持“腿和腰先带动、手握兵器随躯干推进、短促释放、持续收势”。它们不支持把所有动作套成相同的蓄势占比，也不证明原版采用本项目的新四式。

源枪戟映射使用较长端点和自己的骨架比例，部分端点样本低于映射地面；本项目的大锤必须按自身锤头体积检查离地高度。不能直接复制这些坐标、源单位半径或 `worldScale=12.5` 的力值。

## 原创大锤四式建议

采用双手、腰腿主导的四式，保留附件约一秒量级的重兵器节奏，再按本项目角色比例、锤头质量感和可操作性调校。具体持续时间与碰撞窗口由项目实现记录，不能标为原版大锤数据。

1. **侧扫**：后脚支撑、身体先侧转，双手将锤头带到身侧；前踏换重心后突然横向甩出，身体继续少量转动消化惯性。
2. **反扫**：承接前式侧向收势，交换支撑脚，以反向腰转带出低斜扫；接触后锤头继续走完弧线，不立即反弹到待机。
3. **回身提锤**：顺着前式末端转身，将锤头从低处带到肩侧高位；短促扫出后继续提起，给末式提供可见的高位准备。
4. **踏地砸落**：双手高举、髋下沉、前脚重踏，身体前压把锤头砸至前方近地；短暂维持压锤姿势，再通过腿和胸躯收回。命中敌群时给予明确推散，近地重击才产生地面接触反馈。

蓄势、100–150 毫秒量级的集中释放、接触后的停留与回收可以作为本项目原创调校起点；不能将这些推荐范围写成已从原版大锤提取的帧数据。连击间要让上一式末端承接下一式准备，实际前踏和侧步由主角根坐标完成，并让足部支撑随实际移动更新；敌人、场景障碍及场地边界限制可达距离。

伤害应跟随**锤头的连续扫掠**，双手握点与柄方向保持一致；手柄与未经过敌人的另一侧不能因为夸大的光效而造成伤害。末式锤头不得穿地，接地尘、石面火星和碎屑应出现在实际锤头接近或碰到的位置。这里的双手握距、锤头尺寸、移动预算和反馈参数属于原创项目设计，没有从附件获得对应的大锤数值。

## 反馈借鉴与不能声称的内容

`combat.js:358, 388` 的 `startForce/addForce` 作用于攻击者；敌方击退由 `combat.js:1265` 与 `reaction-rules.js:8` 处理。后者记录普通受击力 40、重击波 30、魔法 10，距离还受目标质量和阻尼影响；不能把更大的主角出招力说成更大的敌方击退，也不能把这些源值原样搬进本项目。

附件将挥动、接触、重击波和镜头反馈分开：`main.js:176` 挥击播放 `referenceSwing`，`splash` 播放 `referenceBoom`；`:186` 对重击层调用 `hitcam2(1)`；`reference-hit-feedback.js:7–19, 50–55` 单独生成接触闪光和受击反馈。新大锤可据此使用更短的轨迹尾迹、集中在锤头接触处的亮核、钝击碎屑、低频撞击与重砸尘效，让反馈服务真实锤路。

此次附件仅提供音频文件引用，未实际试听对应音频；不能根据 `hammer.mp3` 名称断言原版音色、频谱或播放节奏。`main.js` 虽有 `hitStop` 变量和扣减逻辑，读取全部赋值未发现正值设置；因此本项目新增的短命中停顿是原创反馈调校，不能称为从该附件核验到的原版精确停帧。

本次没有新增原版实机视频观察。此前实际观看的视频及其观察边界记录在 [大刀视频研究](GREAT_DAO_VIDEO_REFERENCE.md)，其中技能表现也不能作为原版普通大锤四连的证据。新大锤的模型、动作曲线、程序化音效和接触特效应由项目原创实现，不搬运附件所引用的游戏模型、贴图或音频资源。

## 本项目 v0.8.0 实现

新增 `great-hammer` 双手长柄大锤，与双刀、砍刀、大刀并列可选。四式是原创曲线，时长0.98／1.06／1.14／1.24秒，合计4.42秒；释放起始相位0.43／0.44／0.43／0.47，主要快抡集中在随后的约0.24～0.30秒，其后持续刹停和收势。上一式末端直接承接下一式，保留身体与脚步连续性。

锤头实体尺寸0.54×0.38×0.38米，右腕至锤心1.25米，双握距离0.22米。模型、曲线、音色和效果由本项目制作。四式真实前进预算0.40／0.46／0.56／0.64米，总预算2.06米，实际位移按敌距、障碍和地图边界缩短；前脚落稳后后脚收跟，收势不回拉世界坐标。

攻击窗口只检查锤头中心的连续轨迹，采用紧凑圆柱接触原型：水平半径0.27米，垂直半高按当前真实锤头旋转包围盒投影；不是杆身全长伤害，也不是模型逐三角碰撞。窗口边界裁切保留快速挥出和收尾的有效段，蓄势及收势不额外伤害。实际锤头八角点最低高度约束在铺地之上，末式最低点进入地面上方0.025米范围才触发径向尘浪、短暂裂痕与冲击圈，普通高位抡击没有凭空砸地效果。

命中处有短促钝击亮核、碎尘、低频撞击与敌人硬直；末击加大推散及镜头冲击。主角挥锤不因命中冻结，画面尾迹只记录真实锤头轨迹。移动和翻滚优先接管，暂停冻结效果，重开清空粒子、痕迹与旧脚锚。最终验证和 Pages 来源记录见 [VALIDATION.md](VALIDATION.md)。
