# 原版动作风格复核与原创大锤重构依据

日期：2026-10-15（Asia/Shanghai）。研究输入仅为本次 `src.rar` 解压的 本次附件 `src/`。当前 `src/customHammer` 只用于确认 v0.16 的差距。未读取被删除的大锤实现、历史大锤动作或 Git 历史。该文档是源码研究报告，不是测试报告；本任务没有运行测试。

## 1. 结论

用户对 v0.16 的判断有明确源码依据。原版风格的中心是**大幅全身转动、起手冲进、交叉换步、腾跃或弹起、在很短的释放段叠加覆盖身体周围的大型挥击能量面**。角色的动作能力不因武器沉重而变成缓慢站桩。重量感来自短促爆发后的停顿、膝髋缓冲、快速回位与更强的命中反馈。

v0.16 的原创大锤侧重双手固定握持、实体锤头扫掠、鞋底接地及轻微踏步，但髋部最大摆幅只有约 40°，步长 `.20–.32`，跑步脚部抬高 `.16`，视觉反馈主体是小型实体残影和中性色尘屑。这些技术约束没有产生原版的全身大幅旋转与夸张敏捷，因此需要重构编舞、移动和视觉效果，而不是只加一点粒子。

## 2. 可以直接核对的原版源码

以下行号均相对于本次新附件的 `src/`。

### 攻击有独立的释放与回收时钟

- `reference-ordinary-animation.js:7–18`：攻击播放 layer 1 的 attack，基础速率 `.24 + atkspd`；独立排队播放 recovery，速率通常为 `.24`。
- `reference-motion.js:63–78`：将 attack 与 recovery 各自原始时间映射到总体动作，相同动作中的两段不会简单拉成均匀速度。
- `reference-curve-hermite.js:10–12`：曲线按入/出切线执行三次 Hermite 插值，真实的储力、加速、过冲与制动来自分段切线。
- `reference-motion-data.js:555`：原版三种武器各 5 连击的动作、攻击时长、回收时长和曲线身份。此处是打包数据，应通过模块导出读值，避免输出整条大数据行。

### 攻击是全身动作，允许明显转身与跃起

- `reference-motion.js:189–213`：同一时钟更新髋、胸、头、双侧上臂/前臂/手、双侧大腿/小腿/脚和武器，同时更新肩、头和大腿根的位置。
- `reference-curve-motion.js:76–90`：先采所有位置/旋转/缩放，再更新完整骨架世界变换。
- `reference-curve-motion.js:213–230`：保留源髋偏移并修正最低鞋底。这里只把角色移出地面，没有强制每只脚永远钉在同一个世界坐标；原版仍允许抬膝、后踢、旋步、腾跃。
- `reference-motion-data.js:117` 的元信息确定骨骼顺序及 actorScale；新分析脚本读取连续采样器，不复制关键帧到新武器。

### 攻击会冲进，收势时马上可以重新移动

- `combat.js:362–374`：起手时设置 `speedFactor=5.2` 与前向 `moveDirection`，并执行各击自己的起手冲量。
- `reference-attack-rules.js:60–96`：原版双刀起手冲量包含 `120/120/0/150/0`；刀前三击 `110/110/110`；原长柄前三击 `160/130/90`，命中特效启动时还可能添加 `90/120/200` 等冲量。
- `combat.js:397–404`：挥击显示启动时才施加 descriptor 的第二次冲量。因此起手移动与释放移动可以错开。
- `execution-rules.js:24–37`：冲量转为速度后按离散阻尼衰减；玩家质量 `2`、阻尼 `5` 见 `reaction-rules.js:3`。
- `combat.js:2110–2115`：常规普通平移在 `1t–4t` 恢复段、状态允许时重新开放。不能误读为攻击全程按 `speedFactor` 持续跑动；攻击内主要位移来自上面的冲量。

### 常态移动本身很灵活

- `reference-player-movement.js:3–6`：输入因子 `6.5`、初始 `7`，衰减 `2/s`；跑阈值 `4.5`；转向速率 `8/s`。
- `reference-player-movement.js:25–46`：高因子立刻跑，随后转为减速走；跑动画原始速率 `.6`；走动画随速度因子变化；转身用归一化 Quaternion.Lerp。
- `reference-motion-data.js:558`：各类 run 原始片长约 `.333333`，所以 run 的周期是 `.333333/.6≈.556s`。walk 原始片长 `.466667`，配置 `.9` 时周期 `.519s`，实际走速还会改变该周期。
- `reference-animation-blending.js:1–4`：常态移动 CrossFade 的源默认过渡 `.3s`。
- `combat.js:1772–1782`：移动距离、动画请求和 locomotion 时钟由同一更新推进，脚步并非与根移动完全脱节的装饰。

### 特效是战斗轮廓的重要组成

- `reference-attack-rules.js:10–19`：普通挥击 atlas 为 `2×2`、`20 fps`，显示 `.20s`、碰撞短窗口 `.10s`；不同攻击有明显的倾斜平面、起点和缩放。
- `reference-attack-rules.js:65–73`：双刀多数每击有两次独立、错时或错位的挥击面。丰富感来自叠层的动作事件，不只是增加常驻发光。
- `reference-attack-rules.js:75–96`：普通刀 scale `[1.6,2,2]`，原长柄 `[2,2.6,2.6]`，EX 可达 `[2.4,2.4,2.4]`；还会插入独立地面 splash。
- `reference-swing-feedback.js:21–36`：基本挥击面是宽扇形 ribbon。普通布局四阶段弧长 `110°→250°→245°→310°`；EX1 为 `150°→265°→335°→325°`。这对应从短蓄势痕迹到整片扫击，再转为薄余波的视觉节奏。
- `reference-swing-feedback.js:132–140`：普通挥击根节点随角色移动/转向，以 `12.5 × scale × planeHalfExtent` 放大；不是只跟随武器端点的小残影。
- `reference-swing-feedback-data.js:3`：`planeHalfExtent=.15561017`，乘 worldScale12.5 后约 `1.945`；普通 scale2 的长轴半径约 `3.89`，原长柄 scale2.6 为约 `5.06`。这是源反馈平面包围盒尺度，**不等于真实伤害半径或完全不透明的圆盘**，不能把这个数字直接照搬成无依据的群伤。
- `reference-swing-feedback.js:137–147`：普通面使用 additive，EX2 为 multiply 面加 additive glow；地面冲击使用 crack 及多个竖向火焰面。材质/明暗层次同样影响丰富感。
- `reference-swing-particles-data.js:2`：玩家 Pt_hit 启动 burst `10–12`，能量 `.2–.3s`，粒子尺寸 `.03–.05` source 即 `.375–.625` world，随机分量速度 `[2,2,2]` source，world-space，一次发射。
- `reference-swing-particles.js:64–76`：粒子从随角色的发射点出生，然后独立留在世界，保留少量根速度。这给冲刺/挥击留下明显的速度痕迹。
- `reference-swing-feedback.js:141–167`：splash 在显示时锁定世界位置，并保留地面裂痕/上升面；主持续 `1.5s`，而挥击本身仅 `.2s`，有短爆发和长环境回响的对比。

### 击败后有独立碎裂身体的原版先例

- `reference-hit-feedback.js:67–113`：live actor 死亡后选择替换身体，拆为髋/胸/头和四肢等 `11` 个部件。
- `reference-hit-feedback.js:115–145`：复制可见身体几何及材质，由各部件分别推进位置、旋转、缩放，不是把整个完整角色抛出去。
- `reference-hit-feedback.js:147–150`：替换体再向地面下落，显示持续 `3s`。
- 本次“破碎”应是新作者实现的锤击碎裂风格，无需复制这些死亡曲线。关键是伤害归零当帧隐藏完整 live root，独立实体碎块成为可见替代。

## 3. 连续曲线的定量分析

连续采样数据与分析脚本保存在本次工作目录；运行代码不加载这些研究数据。

每条动作在完整时长内取 601 个连续曲线点，攻击段统计只截取到 attack 结束。旋转路程定义为相邻**世界四元数最短角距离**之和，单位度；它是三维累计转动量，不应误称为净偏航角。运行时不加载这些测量数据，也不把源姿态应用到自创大锤。

| 原版动作 | 攻击秒 | 回收秒 | 髋累计转动 | 胸累计转动 |
|---|---:|---:|---:|---:|
| 刀 1 | .417 | .417 | 215° | 376° |
| 刀 2 | .417 | .417 | 269° | 327° |
| 刀 3 | .417 | .139 | 247° | 257° |
| 双刀 1 | .694 | .417 | 396° | 642° |
| 双刀 2 | .833 | .278 | 410° | 462° |
| 原长柄 1 | .556 | .417 | 322° | 312° |
| 原长柄 2 | .833 | .278 | 293° | 272° |

这些值说明“全身翻转/回摆/转身”构成攻击本身。即使部分数值来自姿态的回摆而非单向整圈旋转，几十度范围内的髋胸摆动仍明显偏小。

常态移动测量（已乘源 actorScale `.57112495`）：

| 指标 | 走路 | 跑步 |
|---|---:|---:|
| 左右大腿世界方向最大夹角 | 约 52° | 约 114–119° |
| 单膝最大弯曲角 | 约 75° | 约 139° |
| 单脚前后局部行程 | 约 .45 | 约 .68 |
| 髋垂向范围 | 约 .56–.59 | 约 .45–.63 |
| 单脚抬高范围（脚关节高度） | 约 .04–.20 | 约 .03–.59 |

坐标值属于源角色比例；重构需要按当前 hero 身高换算。脚关节高度包含真实足姿态与 retarget 后的脚底修正，不能当成单独的无条件抬脚指令。实际编舞要保留接地足与摆动足交替，跑步时有高抬膝、后踢和髋起伏；单纯把小步正弦频率加快不够。

## 4. 原创三击的编舞方向

以下是风格目标与起点建议，不是要求照搬源角度、曲线或伤害范围。

### 一击：交叉旋步的大横扫

- 从侧后储锤，前脚交叉或斜跨，髋先转、胸跟进、锤头最后穿过前方；横向轮廓大于一整个身宽。
- 总体约 `.72–.82s`、释放在 `.22–.37s`；攻势向前可约 `1.0–1.3` 当前世界单位，另有小侧移；碰到目标/墙体由碰撞截停。
- 躯干累计转动目标约 `180–260°`，包含蓄势回摆和释放；避免头/躯干一直朝正前方。
- 余势把锤头送到另一侧，直接成为二击的起点，不能每击回到同一个正面 guard。
- 特效：一片厚实能量扇、外缘较亮、内缘有空隙，伴随两三道气流弧；脚部推进留下短尘丝。保留锤头残影，但残影不能占据全部视觉设计。

### 二击：换脚旋升的反向上挑

- 接住一击低侧位置，后脚蹬地、换支撑脚，身体快速回旋，锤头斜向外上方拉起；释放有明显的上升轮廓。
- 约 `.76–.86s`，第一击接二击的起势不再额外长时间蓄力；弹步期间髋可升起，避免看起来被锤重压住。
- 可约 `.85–1.2` 前进及反方向的短侧移，整体像绕近敌人的敏捷进攻，而不是单向滑轨。
- 特效：有纵向倾角的厚挥面，几条后随短线，命中闪点与实体碎屑；横扫与挑击的特效平面必须一眼分得清。

### 三击：短腾跃过顶砸击

- 从二击高位顺势提锤，蹬地腾起、前进，锤头先上举再高速下砸；落地双膝压缩、躯干短停，再快拔锤恢复移动。
- 约 `.95–1.05s`，落锤约 `.48–.62s`；纵向高度和落地压缩要明显，但避免为了模仿源双刀把角色无限抬高。
- 腾跃解除两脚同时锁地的约束，支撑切换与落点对齐根运动；落地后快速接走/跑，沉重的是撞击。
- 特效：沿真实锤头下降方向的竖向压缩能量面、接触帧的亮核和放射碎屑、接地点裂纹/碎石/尘墙，外圈较薄且渐隐；地表反馈只在实际落地发生，不用视效制造假命中。

### 常态移动和取消

- 双手仍固定握一根刚性柄，但跑动握姿允许偏侧持锤、肘部弹性与胸髋对扭；武器不能把上半身完全冻住。
- 跑步使用明显前蹬后踢、交替支撑、躯干前倾和有节奏的重心起落；步频接近 `.55s` 周期的原版精神并与实际速度挂钩。
- 攻击旋转期间鞋子要随支撑转动/旋步，不能所有 foot end quaternion 永远 identity；落地只限制接触时段，而不是全动作固定世界脚锚。
- 大幅身体旋转时，现有 `headYaw=-(pelvisYaw+chestYaw)*.68` 会把颈部扭出正常范围。头部目标应限幅约 ±55°，开始时预判目标，过身阶段随躯干自然跟转。
- 在攻击可取消/恢复段允许立即接移动或闪避；切换时有短姿态过渡，保留实时脚步时钟，避免角色在收招后“凝住再启动”。

## 5. 破碎反馈建议

- 命中未击败时保持短促受击压缩；死亡当帧关闭原角色可见性及碰撞，不让整个完整敌人先飞一段再碎。
- 以实际受击姿态的身体网格切分，保留敌人的肤色、护甲、层次和朝向；破块轮廓应为角状体块，避免统一小球/随机火花代替实体破碎。
- 爆散速度以局部震裂为主，再受重力落地，少量碎片弹跳；粒子与尘雾作为辅层。
- 原地破碎的重心不应离敌人死亡点过远；在可控时间内淡出并回收，不影响新敌人索敌/碰撞。
- 新机制应独立作者实现，沿用原版“live body 被独立碎片替换”的表现原则即可。
